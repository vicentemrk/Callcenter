**Funciones agregadas o modificadas:**
- marvel/services.py:
  * mapear_elemento(tipo, registro) -> dict: traduce el JSON de la API a
    campos del modelo. movie/tvshow usan title/overview/cover_url/
    release_date/phase/saga; character usa name/description/image_url
    (los personajes quedan sin fecha/fase/saga). Los nulos o vacios
    quedan en None; nunca se inventan datos. Helpers internos:
    _texto (limpia y devuelve None si vacio), _fecha (parsea

    comparar_json=True) -> estado: upsert idempotente identificado por
    (tipo, mcu_id). Estados devueltos: creado (no existia),
    actualizado (existia y cambio al menos un campo mapeado o el JSON
    original), sin_cambios (existia y NADA cambio; NO se regraba, por
    lo que repetir la sincronizacion no toca el disco ni reescribe
    sincronizado_en), incompleto (sin mcu_id valido o sin nombre, no
    se guarda), error (fallo de escritura, logueado, el proceso
    continue con el resto). comparar_json=False es un param de prueba.
    Comportamiento anterior: no existia.
  * sincronizar_tipo(tipo, limite=None, tamano_pagina=10,
    cliente=None) -> stats: recorre las paginas de la API (via
    _links.next del envelope real) hasta agotarlas o alcanzar el
    limite por tipo. Devuelve {tipo, procesados, creados,
    actualizados, sin_cambios, incompletos, errores, paginas,
    total_api, acotado}. 'acotado' True = se detuvo por --limite
    (sincronizacion parcial), no por agotamiento de la API.
    Salvaguarda anti-ciclos: si la API anuncia 'next' pero llega una
    pagina vacia, corta con log WARNING en vez de girar infinito.
    'cliente' permite inyectar el ClienteSimulado en pruebas.
  * sincronizar_catalogo(tipos, limite, tamano_pagina, cliente):
    ejecuta sincronizar_tipo por cada tipo en orden y devuelve la
    lista de estadisticas (aun sin uso por el comando, que lo hace a
    mano para reportar cada tipo por separado; queda como API del servicio).

  * class Command(BaseCommand) con help legible; add_arguments define:

    Django: consola).

**Sintaxis definitiva del comando:**
- python manage.py sincronizar_mcu                          -> completo, todos los tipos
- python manage.py sincronizar_mcu --tipo movie --limite 10  -> parcial
- python manage.py sincronizar_mcu --tipo tvshow --limite 10
- python manage.py sincronizar_mcu --tipo character --limite 10
- python manage.py sincronizar_mcu --tipo todos --limite 10 --pagina 10
- Para sincronizacion completa (aun NO ejecutada): --tipo movie sin --limite
  (recorre todas las paginas del tipo respetando limites de la API).
  Sin --limite y --tipo todos recorre el catalogo entero (respecto a los
  conteos: 75 peliculas, 56 series, 375 personajes).

**Transformacion de datos (mapeo real):**
- id -> mcu_id (int >= 1; si falla, registro incompleto).
- title/name -> nombre; overview/description -> descripcion;
  cover_url/image_url -> imagen; release_date -> fecha_estreno
  (date, formato 'YYYY-MM-DD' verificado); phase -> fase (int);
  saga -> saga. JSON original completo -> datos_json; now() ->
  sincronizado_en (utc). Nulos gestionados como None / sin dato.

**Cambios en la base de datos:**
- Ningun cambio de esquema (se usa marvel.0001_initial ya aplicada en B2).
- Escrituras: 30 registros NUEVOS creados en marvel_elementocatalogo
  (10 movie, 10 tvshow, 10 character) con la ejecucion limitada
  autorizada. La repeticion creo 0 registros y marco 30 'sin_cambios'.
- Sin relaciones con Preguntas (postergado a C1, aprobado en concepto).

**Decisiones tecnicas:**
- Upsert manual (get + comparacion + create/save) en lugar de
  update_or_create bruto: NUNCA se graba cuando nada cambio
  (update_or_create regrabaria y reescribiria sincronizado_en cada
  vez, rompiendo la idempotencia observable exigida).
- Tope del limite antes de procesar cada registro: la sincronizacion
  parcial nunca guarda 'de mas' (30 = 10 por tipo exacto).
- 429 (rate limit) no aborta todo el comando: hace skip del tipo
  afectado con aviso; los demas errores generan exit code 1 al final.
- Sin fallback CDN en esta fase: el respaldo jsDelivr se evalua para
  B futuras; la API respondio estable en todas las pruebas, y el
  cliente tolera caidas reusando MCUAPIError.
- Sin desactivacion de ausentes: no toca activo=False aunque la
  sincronizacion sea parcial AND la API reporte totals: se requiere
  recuperacion COMPLETA del tipo + integridad + autorizacion.
